# 管理員進度與清單整理

新增「已通知店家」「已取消調貨／看貨」「商品已售出／無法提供」「客人已到店看貨」「客戶已購買／成交」「看貨後未購買」「客人未赴店」。既有收到需求、確認、調貨中、運送中、商品到店與無法調貨保留，內部原因新增店家認為單價太高。原商品已售出與本次客戶成交分開登記；成交紀錄不等同付款驗證。

取消及看貨結果需要管理員備註，客戶 App 時間軸只顯示固定公開文字，店家內部原因不公開。登記「已通知店家」須填店家並由管理員確認確實聯絡過；系統不代為聯絡店家。結果可重新確認／重新安排，紀錄與版本檢查保留。

調貨中和運送中統一淡黃色底。管理員每頁六筆、支援最新／最舊／最近更新／依進度排序；每筆旁有編輯／整理和刪除／封存／復原。測試需求標示刪除，正式需求標示封存，皆可復原，安排未取消。移出清單不刪資料，也不影響客戶原連結。追蹤待辦預設收合。

驗證：pnpm test、pnpm lint、pnpm build:pages；supabase/tests/lifecycle.sql 以合成需求和 rollback 驗證取消、重開、店家通知、所有看貨結果、內部原因保密、版本衝突、權限、六筆分頁與四種排序、正式需求封存／復原。
