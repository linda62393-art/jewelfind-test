# 看貨後回饋與需求管理

客戶在「我的看貨需求」開啟原有專屬需求頁，商品到店通知發佈後可填寫看貨後回饋。六個選項：已購買、款式不合、價格太高、服務／答覆不清楚、考慮中、想看其他款；選填願付價格與想找的商品，並自行勾選是否願意收到推薦。看貨日期預設當天，可展開修改。

管理員可發佈 App 回饋邀請、依客戶實際表達代填、查看歷次回饋，並記錄聯繫內容、下次聯絡日期及待回饋／待追蹤／已聯繫／已結案狀態。追蹤待辦可篩選今日到期及逾期、未結案或指定狀態。內部聯繫筆記不向客戶公開，代填回饋會顯示給客戶。暫不聯絡的需求不可排聯絡日期。邀請每日最多一則，不發送 LINE 或手機推播。

需求卡片依原處理狀態顯示灰／藍／黃／紫／綠／紅底色。需求管理工具可編輯管理清單顯示名稱及測試標記；原始客戶資料保留。標記為測試後可以可復原刪除；一般清單及追蹤待辦隱藏該需求，勾選「查看已刪除的測試需求」可開啟並復原。這是 soft delete，資料庫不永久刪資料。

回饋以每次更新新增事件保存，版本檢查防止覆寫另一人的回饋；追蹤紀錄另有版本檢查。私有資料表啟用 RLS 並撤銷客戶直接讀寫，RPC 依原專屬需求憑證或管理員權限檢查存取。

商品、原始類別／風格／材質需求與回饋可依 request_id 連結。願付價格是客戶自述，不是实际成交價；購買結果是客戶回報，不是訂單付款驗證。資料目前仍需累積，未新增對店家報表、資料分享或廣告系統。未來統計應去識別化、排除測試需求，採每筆需求最新回饋避免重複計數，區分客戶自填與管理員代填，呈現樣本數，分開分析願付價格和回報購買數。

檢查：pnpm test、pnpm lint、pnpm build:pages；SQL Editor 執行 supabase/tests/aftercare.sql，以合成需求測試權限、並行更新、歷史保留、內部筆記隔離、追蹤待辦、刪除與復原，所有測試資料回滾。

客戶清單每頁六筆，可改清單名稱、釘選、可復原刪除，保存於使用者目前瀏覽器，不會改寫原始需求或取消店家安排。進度顯示同一筆需求內的時間軸（台灣時間至分鐘），預設最近三則，其他歷史可展開；當初收到需求時間亦保留。確認中與調貨處理使用內部狀態的實際更新時間，但文字採固定客戶版本，不洩露內部備註；到店地址只顯示目前有效安排。看貨意願與看貨後回饋可收合。
